# F036 Structured Errors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every error the API returns for a bad request is structured, uses a closed set of codes and fixed messages, and never reflects a received value, a received key name, a header value or a parser message; schema failures return `{path, code}` details from `@decidere/schema`.

**Architecture:** A small `apps/api/src/errors.ts` owns the error contract (codes, fixed messages, HTTP status, body builder, a reply helper for validation failures). `buildApp` uses it in the not-found and error handlers, maps Fastify's body-parser error codes to closed API codes, and gets a `bodyLimit` option. No ingestion route is added here: F040 mounts `POST /v1/messages` and calls the helper. Tests use test-only routes registered inside the test, like the existing `/boom` test.

**Tech Stack:** Fastify 5.12.8 (already installed), `@decidere/schema` as an npm workspace link, `node:test`, Node >= 22.18 type stripping.

**Spec:** `feature-list.json` F036 (acceptance: an unknown key never appears in the error; an invalid value is not reflected; structured error, never a thrown string); `docs/adr/ADR-001` (no payload in errors or logs); `docs/adr/ADR-008` (error codes, F040 gates); AGENTS.md "Convenciones: Errores / Logging".

## Global Constraints

- Error body shape stays `{"error":{"code","message","request_id"}}` and gains an optional `details` only for `validation_failed`: an array of `{path, code}` copied from `validateMessage` (closed `ValidationError`, never rebuilt from the request).
- Messages are fixed strings per code. No template, no interpolation, no `error.message` from Fastify, Ajv or V8, ever.
- Closed API codes: `not_found`, `bad_request`, `invalid_json`, `payload_too_large`, `unsupported_media_type`, `validation_failed`, `internal_error`. Status: 404, 400, 400, 413, 415, 422, 500.
- Fastify parser error mapping (verified with Fastify 5.12.8 on Node 26): `FST_ERR_CTP_INVALID_JSON_BODY` and `FST_ERR_CTP_EMPTY_JSON_BODY` (also what `__proto__` and `constructor.prototype` keys produce) -> `invalid_json`; `FST_ERR_CTP_BODY_TOO_LARGE` -> `payload_too_large`; `FST_ERR_CTP_INVALID_MEDIA_TYPE` -> `unsupported_media_type`; any other 4xx -> `bad_request`; everything else -> `internal_error`.
- Logging on failure: only `{ code, status }` of the API error plus the existing `{ name, code }` of the thrown error. Never body, headers, params, query or `error.message`. `/health` stays unlogged.
- `x-request-id` is generated by the server (existing); every error body carries it.
- Thrown non-Error values (string, null, plain object) must produce the generic 500; the handler must never throw itself.
- Do not edit existing tests. New tests go in new files.
- Dependency: `@decidere/schema` is added to `apps/api` as a workspace link (`"*"`); no external package is added. Use `--registry=https://registry.npmjs.org/` and check the lockfile resolves only to registry.npmjs.org plus the workspace link. This needs the user's approval (see Approval items).
- Out of scope (F040): the real `POST /v1/messages` route, `source` allowlist, `instance_id` handling, pre-`JSON.parse` checks for duplicate keys and exponent notation, persistence.

## Approval items (decide before Task 1)

1. Workspace dependency `@decidere/schema` in `apps/api` (no external package).
2. HTTP statuses: 422 for schema failures, 400 for malformed JSON (alternative: 400 for both).
3. `buildApp` gets `bodyLimit` with default 262144 bytes (a maximal valid message is far below 256 KiB; Fastify's default is 1 MiB). ADR-008 assigned `bodyLimit` to F040; this plan only sets the default and the option so 413 can be tested.

## Review Focus

1. A body whose unknown key is a canary, at root, instance and variable level, sent through a test route that calls `validateMessage`: the canary never appears in the body, headers or logs (Task 2).
2. Malformed JSON with a canary fragment: V8's SyntaxError text can include it; the response is the fixed `invalid_json` and logs hold no fragment (Task 1).
3. Keys `__proto__` and `constructor.prototype`: Fastify rejects them; the response is `invalid_json`, no pollution of `Object.prototype` (Task 1).
4. Wrong or hostile `content-type` (a canary media type), empty body, body over the limit: fixed codes, header value not echoed (Task 1).
5. `throw "string"`, `throw null`, `throw { message: canary }`, rejected promise with a string: generic 500 with request id, handler does not crash (Task 1).

### Task 1: Error contract and parser-error mapping

**Files:**
- Create: `apps/api/src/errors.ts`, `apps/api/src/errors.test.ts`
- Modify: `apps/api/src/app.ts`, `apps/api/package.json`, `package-lock.json`

**Interfaces:**
- Produces in `errors.ts`:
  - `export type ErrorCode = "not_found" | "bad_request" | "invalid_json" | "payload_too_large" | "unsupported_media_type" | "validation_failed" | "internal_error"`
  - `export const STATUS: Record<ErrorCode, number>` and `export const MESSAGES: Record<ErrorCode, string>` (fixed strings, English, ending with a period like the existing ones)
  - `export type ErrorBody = { error: { code: ErrorCode; message: string; request_id: string; details?: ValidationError[] } }`
  - `export function errorBody(code: ErrorCode, requestId: string, details?: ValidationError[]): ErrorBody`
  - `export function codeFor(error: unknown): ErrorCode` — total function over any thrown value: reads only `statusCode` and `code` when they are a number / string, applies the mapping in Global Constraints, never reads `message`.
- `buildApp` options: `BuildAppOptions` gains `bodyLimit?: number` (default 262144) passed to Fastify.
- Consumes: existing `buildApp`, `LogController`, `errorBody` call sites in `app.ts` (replace the local `MESSAGES`/`errorBody`).

### Task 2: Validation failures reuse the schema package's closed errors

**Files:**
- Modify: `apps/api/src/errors.ts`, `apps/api/src/errors.test.ts`
