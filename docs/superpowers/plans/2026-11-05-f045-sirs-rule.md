# F045 SIRS v1 rule (transcribed, cited, inactive) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sepsis.sirs.v1` exists as a validated YAML rule with a verified citation, `severity: watch` and `clinical_approval: pending`, tested end to end through the engine and the class policy, but not part of the active rule set.

**Architecture:** The rule lives in a sibling directory `knowledge/rules-candidate/` that the API never loads (`RULES_DIR` defaults to `knowledge/rules/`). Tests load that directory with `loadRuleSet`. Activating SIRS later is a `git mv` into `knowledge/rules/` plus the test updates that decision implies (an "activation preview" test pins what changes). Four SIRS criteria are expressed as `atLeast 2` over four `any` groups so each published alternative is a leaf.

**Tech Stack:** YAML rule files, TypeScript, `node:test`. No new dependency.

**Spec:** `docs/progress/feature-list.json` F045 (criteria: stable id `sepsis.sirs.v1` with citation; `clinical_approval = pending`), ADR-002, ADR-007, ADR-010 (class policy), ADR-012 (PaCO2/bands optional; completeness counted by criteria, decided for F047), AGENTS.md ("Reglas clínicas": thresholds are a clinical decision, cited with version and section).

## Decisions taken with the user (2026-11-05)

1. **Inactive:** SIRS is not activated. Placing even a disabled file in `knowledge/rules/` breaks two existing tests that load that directory with the narrow variable set `{resp_rate, sbp, gcs}` (`packages/rules/src/qsofa.test.ts`, `qsofa-policy.test.ts`), and activating it turns every qSOFA-normal message into `revisión clínica` and breaks ~6 more. The separate directory leaves all existing tests and `rule_set_version` untouched.
2. **Severity `watch`** (provisional, clinician to confirm): SIRS ≥ 2 alone yields `vigilancia`, never `crítico`; the infection proxy (F046) is blocked.
3. **Full criteria:** the four published criteria with their alternatives, including PaCO2 and immature bands (faithful to the source, consistent with ADR-012).

## Global Constraints

- No threshold is written from memory: Task 1 Step 1 verifies every value below against the primary source and records the exact table/box and version. If the source differs from any value here, stop and report BLOCKED; do not adapt silently.
- Proposed thresholds (SIRS ≥ 2 of 4 criteria): temperature `> 38` or `< 36` `Cel`; heart rate `> 90` `/min`; respiratory rate `> 20` `/min` or PaCO2 `< 32` `mm[Hg]`; WBC `> 12` or `< 4` `10*3/uL` or immature (band) forms `> 10` `%`. Comparisons are strict (`>` and `<`).
- Every condition `unit` equals the catalog `ucum` of its variable (the F068 rule), and every variable is in `DELIVERABLE_VARIABLES`.
- `id: sepsis.sirs.v1`, `format_version: 1`, `severity: watch`, `clinical_approval: {status: pending, approver: null, guideline_version: null}`; file name `sepsis.sirs.v1.yaml`; `title` must not say "sepsis" as a diagnosis (use "SIRS: criterios de respuesta inflamatoria sistémica", like qSOFA's screening wording).
- `knowledge/rules/` is not modified; `loadActiveRules(DEFAULT_RULES_DIR).rule_set_version` stays `rs-810ea5889733ed08`. No existing test is edited. No new dependency.
- Branch `feat/f045-sirs-rule` from `main`; no push without approval. `npm run verify` and `npm run scan:phi` exit 0 before marking `passing`. Code/commits/plan in English; ADR/PROGRESS in Spanish.

## Review Focus

1. Strict boundaries: temperature 38.0 and 36.0, HR 90, RR 20, PaCO2 32, WBC 12 and 4, bands 10 must all evaluate false (Task 2).
2. Alternatives inside a criterion: RR 22 without PaCO2 makes that criterion true; RR 18 without PaCO2 makes it unknown, not false; a `null`/missing WBC with bands > 10 still makes the WBC criterion true (Task 2).
3. Missing gasometry/bands: with the other four values normal and known, the rule is unknown and the class is `revisión clínica`, never `sin alerta`; with all six variables known and normal it is `sin alerta` (Task 2).
4. Isolation: the real active rule set is unchanged and the API does not load the candidate directory (Task 3).
5. One criterion true with everything else known is `sin alerta` for a `watch` rule (the policy only gives partial-criteria `vigilancia` to critical rules): pin it so the activation decision sees it (Task 2).
