# F049 Tau Sweep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A command (`npm run seeds:tau`) that runs the seeds at a grid of τ values, reports the "% routed to review versus τ" curve on a calibration subset (about 70%), keeps about 30% of the seeds untouched until asked for, and checks a candidate τ for stability (±0.1) and critical safety. It supplies the evidence F049 needs; it does NOT change the default τ.

**Architecture:** Extract the server lifecycle and the sequential POST loop from `tests/runner/run.ts` into a shared module. Add a pure sweep core (deterministic split, per-τ summary, stability check) and a renderer, driven by a thin CLI that spawns one server per τ (τ is an environment variable of the API). A final task runs the sweep on the real seeds and records the findings in an ADR.

**Tech Stack:** TypeScript on Node >= 22.18, `node --test`, Biome. No new dependency.

**Spec:** `docs/progress/feature-list.json` F049, `docs/adr/ADR-015-enrutamiento-por-certeza.md` (points 6, 7 and the "Consecuencias"), `docs/adr/ADR-014-certeza-provisional.md`, `docs/adr/ADR-016-seeds-sinteticos-provisionales.md`, `seeds/README.md`, the F050 runner (`tests/runner/*`).

**Branch:** `feat/f049-tau-sweep` from `main` (F050 is merged).

## Global Constraints

- Code, identifiers, comments, commits: English. Report text printed to the user, ADR/README/PROGRESS: Spanish.
- Report wording: "calibración, no validación"; "conformidad con criterios publicados; validación clínica pendiente" verbatim when conformity is mentioned; `τ` is "provisional, no validado"; never "IA", "precisión", "concordancia", "confianza"; never present a percentage as statistical (fewer than 100 seeds). Describe the certainty as "puntaje determinístico de certeza" if it needs a name.
- Never change a seed label, the default `TAU_PROVISIONAL`, `VARIABLE_BANDS`, `CERTAINTY_VERSION`, or any existing test. The choice of τ is a clinical and product decision (ADR-015 point 8): this feature measures and recommends, it does not decide.
- The held-out subset (about 30%) is never shown by default: no ids, no per-class results, no routed counts, only its size. It is shown only with `--held-out`, which prints it separately and states it was not used to choose τ.
- Output prints only seed ids, classes, counts, τ and versions. No payloads, no secrets (`SEED_API_KEY` is read from the environment and never printed).
- No new dependency. Never evade the PHI hook (synthetic values only). `npm run verify` and `npm run scan:phi` must both exit 0.

## Facts that shape the design (measured before this plan, ADR-015)

- Whole set, 46 seeds: 9 routed at τ = 0.5; 23 routed at τ = 0.6 (8 of 8 `clear_negative` flip at 0.6 because a complete case with GCS 15 has certainty exactly 0.5 and the routing is `value < τ`); the 16 expected criticals stay `crítico` at τ 0.4, 0.5 and 0.6.
- Consequence: "τ stable under ±0.1" cannot hold at τ = 0.5 (it would include 0.6). A candidate at or below 0.4 keeps the 0.3 to 0.5 neighbourhood on the same side of the jump. The sweep must show this, not assume it.

## Exit codes of `seeds:tau`

| Code | Meaning |
|---|---|
| 0 | every expected `critical` returned `crítico` at every τ in the grid and every seed was covered |
| 1 | an expected critical returned another class at some τ (including `revisión clínica`), or a seed was not covered |
| 2 | the sweep could not run (server did not start, seeds file unreadable, bad arguments) |

## Review Focus

1. Held-out leak: the default output must not contain a held-out id or a held-out count of routed cases.
2. Split determinism and size: the same seeds always give the same split; a split with zero expected criticals in either part is reported, not hidden (sensitivity `n/a`).
3. A critical that is not `crítico` at any τ of the grid fails the run, naming the τ and the id.
4. Invalid arguments (`--candidate 0`, `--candidate 1.5`, unknown flag) exit 2 with a fixed message and no stack.
5. τ grid edge: τ = 1.0 is valid for the API (`0 < τ <= 1`) and must run; a candidate whose neighbour τ+0.1 exceeds 1 or τ-0.1 is not above 0 reports the missing neighbour instead of crashing.

### Task 2: Sweep core

**Files:**
- Create: `tests/runner/sweep.ts`
- Test: `tests/runner-sweep.test.ts`

**Interfaces:**
- Consumes: `SeedCase`, `SeedClass` (`seeds/build.ts`); `Observed` (`metrics.ts`).
- Produces:
  - `splitSeeds(cases: SeedCase[]): { calibration: SeedCase[]; held_out: SeedCase[] }` — deterministic: a case is held out when the first byte of `sha256("split:" + id)` modulo 10 is `< 3`. Order preserved.
  - `type TauRow = { tau: number; total: number; routed: number; routed_share: number; routed_ids: string[]; criticals: { expected: number; detected: number; in_review: number; missed: number; requires_confirmation: number }; uncovered: string[] }`
  - `summarizeTau(cases: SeedCase[], observed: ReadonlyMap<string, Observed>, tau: number): TauRow` — `routed` counts responses with `routed_from !== null` (any expected class); a case not in the map or with `class === null` goes to `uncovered`; criticals: `detected` = class `crítico`, `in_review` = class `revisión clínica`, `missed` = any other class or uncovered; `requires_confirmation` counts expected criticals whose observed flag is `true`. `routed_share` is `routed / total` (0 when total is 0).
  - `type Stability = { candidate: number; neighbours: { tau: number; row: TauRow | null }[]; safe: boolean; max_delta: number | null; stable: boolean; reason: string }`
  - `assessStability(rows: ReadonlyMap<number, TauRow>, candidate: number, maxDelta: number): Stability` — neighbours are `candidate - 0.1` and `candidate + 0.1` rounded to one decimal; a neighbour outside `(0, 1]` or missing from `rows` has `row: null`. `safe` is true when the candidate row and every present neighbour has `in_review === 0 && missed === 0`. `max_delta` is the largest absolute difference of `routed_share` between the candidate and a present neighbour (`null` if none). `stable` is `safe && max_delta !== null && max_delta <= maxDelta`; `reason` is a fixed Spanish sentence for each failing cause.
  - `export const STABILITY_MAX_DELTA = 0.1` with the comment `provisional: clinical rule pending (ADR-017)`.

- [ ] **Step 1: Write the failing tests** (synthetic cases and fabricated `Observed`): split is deterministic across calls, partitions the input without loss or overlap, keeps order, and on the 46 real seeds (`seeds/cases.json`) puts between 8 and 20 cases in `held_out` (document the actual number in a comment); `summarizeTau` counts routed (only responses with `routed_from !== null`), counts a critical in review as `in_review` and not `detected`, an unobserved critical as `missed`, `requires_confirmation`; `assessStability`: safe and delta ≤ max → stable; unsafe neighbour → `stable` false with the safety reason; delta above max → false with the delta reason; candidate 0.1 → lower neighbour `row: null` and no crash; candidate 1.0 → upper neighbour `row: null`; no neighbour rows at all → `max_delta` null and not stable.

## Decisions to confirm (defaults chosen, change on request)

1. This feature does NOT change `TAU_PROVISIONAL` (0.5), the bands or any version; it reports and recommends. F049 stays `failing` until the user and a clinician pick τ.
2. Stability rule (provisional): critical safety holds at τ and both neighbours, and the routed share differs by at most 10 percentage points between τ and each neighbour.
3. Split: hash of the case id, about 30% held out, deterministic. The held-out part is read once, after τ is chosen, with `--held-out`.
4. The grid is 0.1 to 1.0 in steps of 0.1, one API process per τ.
