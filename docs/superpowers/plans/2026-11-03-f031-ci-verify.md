# F031 CI with the Verify Command, Secret Scanning and PHI Check: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Actions workflow that runs exactly `npm run verify`, a PHI-pattern scan of tracked files and a secret scan, on every pull request and on pushes to `main`, using the Node version floor from `engines`.

**Architecture:** One workflow file, `.github/workflows/ci.yml`, with three steps after checkout and Node setup: `npm ci` then `npm run verify` (unchanged), `npm run scan:phi`, and a pinned, checksum-verified gitleaks binary. The PHI scanner is a small Python script that imports the regex patterns from the existing Claude Code hook, so the patterns live in one place. Tests live in the existing `tests/` workspace and check the workflow's contents and the scanner's behavior.

**Tech Stack:** GitHub Actions, Node 22.18 (the `engines` floor), Python 3 standard library (scanner only), gitleaks (binary). No new npm dependency.

**Spec:** `docs/superpowers/specs/2026-11-03-mvp-decomposition-design.md` (order 2), feature F031 in `docs/progress/feature-list.json`, `AGENTS.md` ("Definición de terminado": the same verification command runs in CI), plan `docs/superpowers/plans/2026-11-03-f030-monorepo-verify.md`.

## Global Constraints

- The CI verification step is exactly `npm run verify`; the workflow must not re-implement its steps.
- `engines.node` is `>=22.18`; CI pins the floor (`22.18`), which also verifies the gap accepted in F030 (default `*.test.ts` discovery on the floor).
- No secrets, tokens or real patient data in the repo, workflow or tests. Test positives are built at runtime from fragments, never committed as literals.
- The PHI scanner must never print a matched value, only the file path and the pattern name (CI logs are not a safe place for PHI).
- Every third-party action is pinned to a full 40-character commit SHA, with the tag in a comment. Workflow `permissions` are `contents: read` only.
- Never commit to `main`; branch `chore/f031-ci-verify`; Conventional Commits, max 72 chars. One logical change per commit.
- Never edit an existing test to make it pass. Never push without the user's approval.
- Code, comments and docs in English.
- F031 becomes `passing` only with evidence from a real CI run on GitHub.

## Review Focus

1. The scanner echoing a matched value (PHI) into CI logs: Task 1 asserts output contains the path and pattern name but not the matched text.
2. The scanner passing because it scanned nothing (no arguments, unreadable or binary files): Task 1 asserts no arguments exits 2 and reports the number of files scanned.
3. The inherited allowlist skipping any path containing `test`, `fixture`, `mock`, `example` or `.md` (so a future `seeds/latest.json` would never be scanned): Task 1 pins this with a test on `seeds/` paths and the scanner prints how many files were skipped, so it is visible.
4. A mutable action tag or an unverified downloaded binary: Task 2 asserts every `uses:` is a 40-hex SHA; Task 3 asserts the workflow verifies a SHA-256 before running gitleaks.
5. CI silently passing with zero tests on the Node floor: Task 4 reads the real CI log for the test count on Node 22.18.

### Task 1: PHI scanner script and npm script

**Files:**
- Create: `scripts/scan_phi.py`
- Create: `tests/scan-phi.test.ts`
- Modify: `package.json` (add script `scan:phi`)

**Interfaces:**
- Consumes: `PATTERNS` and `ALLOWLIST_SUBSTRINGS` from `.claude/hooks/check_phi_patterns.py`, imported with `importlib` by file path (the hook is not modified).
- Produces: `python3 scripts/scan_phi.py <file>...` exits 0 when no hit, 1 when any file matches a pattern, 2 on no arguments. stdout lines: `<path>: <pattern name>` per hit, and a final `scanned N files, skipped M, hits K`. npm script `scan:phi` = `python3 scripts/scan_phi.py $(git ls-files)`.

- [ ] **Step 1: Write the failing tests** in `tests/scan-phi.test.ts` (`node:test`, `node:assert/strict`, `spawnSync`, `mkdtempSync` in `os.tmpdir()` with prefix `phi-scan-`, run with `cwd` = the temp dir and relative file names so the allowlist matches on the relative path). Positives and negatives are assembled at runtime from fragments (for example `["user", "host.org"].join("@")`, a phone as `"+" + "5700000000"`):
  - `clean file exits 0 and reports one scanned file`.
  - `file with an email-like string exits 1, names the file and the pattern, and never prints the value` (assert stdout includes `sample.txt` and `email_en_texto_plano`, and does not include the generated value).
  - `no arguments exits 2`.
  - `allowlisted path is skipped and counted` (a file named `readme.md` containing an email-like string: exit 0, output contains `skipped 1`).
  - `seeds path is scanned` (file `seeds/case-a.json` containing an email-like string: exit 1).
  - `package.json defines scan:phi` (`scripts["scan:phi"] === "python3 scripts/scan_phi.py $(git ls-files)"`).
- [ ] **Step 2: Run `node --test tests/scan-phi.test.ts`**. Expected: FAIL (script missing; the last test fails on the missing npm script).
