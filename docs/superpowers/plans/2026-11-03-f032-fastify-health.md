# F032 Fastify API Skeleton with GET /health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A minimal TypeScript Fastify API (`apps/api`) that answers `GET /health` with 200, runs under `scripts/init.sh` (exit 0 with the API up), keeps no state in memory between requests, and fixes the error / request-id / caching / logging conventions that F036 and F041 will inherit.

**Architecture:** `apps/api` is an npm workspace. `src/app.ts` exports `buildApp()` (no listening; tests use `app.inject()`); `src/server.ts` reads `PORT` / `API_HOST`, listens, and shuts down gracefully. Node 22.18 runs the `.ts` files directly (native type stripping): no build step, no TS runner. Persistence, validation, auth, `/v1/messages`, CORS and body limits are out of scope (F035+, F040, F053, F054+). `server.ts` is for local/long-running hosts; Vercel (F034) will use its own handler entry around `buildApp`.

**Tech Stack:** Node >=22.18, TypeScript 7 (typecheck only), Fastify 5, `node:test`, Biome (existing).

**Spec:** `docs/superpowers/specs/2026-11-03-mvp-decomposition-design.md` (order item 3; F032 acceptance criteria in `docs/progress/feature-list.json`). Constraints: ADR-004, AGENTS.md "Convenciones" (structured logger, never payloads, errors never echo values) and "Stack" (no in-memory state between requests).

**Reviews incorporated:** backend-engineer and api-architect reviews of the first draft (2026-11-03). Rulings are marked "Ruling" where I decided something the user may want to overturn.

## Items needing the user's explicit approval before execution

1. **Dependency:** `fastify ^5.12.8` (runtime dep of `@decidere/api`). MIT (`npm view fastify license`); latest 5.12.8, last modified 2026-11-02 (`npm view`); transitive deps (pino, find-my-way, light-my-request, etc.) are the same ecosystem. No TS runner, no test library, no `@fastify/*` plugin. Anything else needs a new approval.
2. **Config change:** add `"verbatimModuleSyntax": true` and `"erasableSyntaxOnly": true` to `tsconfig.base.json`, so typecheck (not runtime) catches value-imports of types and non-erasable syntax under Node's type stripping. Implementer must confirm TS 7.0.2 accepts both flags and that existing `tests/*.ts` still typecheck; if not, stop and report.
3. **Behavior change in `scripts/init.sh`:** dependency step becomes `npm ci` (instead of `npm install`, which can rewrite the lockfile through a local mirror) unless `SKIP_INSTALL=1`; the script also fails fast if the port is already answering, and kills the whole API process group on exit.
4. **Ruling (rename):** the host variable is `API_HOST` (not `HOST`, which shells and some environments export as the machine hostname). Default `127.0.0.1`; containers need `API_HOST=0.0.0.0`.

## Global Constraints

- The single verification command is `npm run verify` (lint && typecheck && test && build); the same command runs in CI. Do not change its definition (pinned by `tests/structure.test.ts`).
- `engines.node` is `>=22.18`; CI pins `22.18`. Sibling imports use the `.ts` extension. Types are imported with `import type` (enforced by `verbatimModuleSyntax`). No `enum`, parameter properties or `namespace`.
- Workspace package `@decidere/api`, `"type": "module"`, `"private": true`; its `test` script is plain `node --test`.
- No state in memory between requests: no module-level mutable variables, counters, caches or uptime in responses.
- Logging: Fastify's pino logger only. The request serializer logs `{ method, path }` only (query string stripped; no headers, no remote address, no body). `/health` requests are not logged.
- Every response carries `Cache-Control: no-store` and an `x-request-id` header (a UUID generated by the server; an inbound request-id header is never trusted or echoed).
- Error body shape (the convention F036/F041 inherit): `{"error":{"code":"<snake_case>","message":"<fixed string>","request_id":"<uuid>"}}`. Messages are fixed strings per code and are never built from request data or from `err.message`. 5xx is always `internal_error`. An optional `details: [{path, code}]` is reserved for F036 and is NOT built now.
- `/health` is liveness only (no dependency checks), unversioned (operational endpoint outside the `/v1` contract), response schema `{ status: const "ok" }`, body exactly `{"status":"ok"}`. Wrong method (`POST /health`) returns 404 by deliberate choice (Fastify default; no 405/Allow). `HEAD /health` returns 200 with an empty body. Future feature routes go in a plugin registered with `{ prefix: "/v1" }`; no `routes/` tree is created now. `/ready` is deferred to F054+.
- Config via environment variable (`PORT`, `API_HOST`); do NOT create `.env.example` (`scripts/init.sh` exits 1 when `.env.example` exists without `.env`).
- Never edit or delete an existing test to make anything pass. `tests/structure.test.ts` "init.sh exits 0 ... when apps/api is not scaffolded" self-skips once `apps/api` exists; leave it (one `skipped` in the output is expected).
- The lockfile resolves to `registry.npmjs.org`; install with `--registry=https://registry.npmjs.org/` and re-check (Task 1 Step 5).
- Conventional Commits, one logical change per commit, synthetic data only, no push.

## Review Focus

- Unknown route / wrong method must not return 200, and the 404 body must not contain the requested path (Task 1).
- A thrown error carrying a secret-looking message must not appear in the 500 body (Task 1).
- An inbound `x-request-id` header must not be echoed (Task 1).
- Logs contain no query string, header values or remote address (Task 1).
- Invalid `PORT` (`abc`, `0`, `70000`, empty, `80.5`, `0x50`, `1e3`, ` 80`, `-1`, `+80`) fails loudly (Task 2).
- Port already in use: `start` exits non-zero; `init.sh` (dev/watch mode hides listen failures) must not report a false OK (Task 3).
- `init.sh` leaves no stray `node` process after exit (Task 3).
