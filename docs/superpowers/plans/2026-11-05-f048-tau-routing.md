# F048 τ from the environment and routing of non-critical cases to review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** τ is read from the environment (`CERTAINTY_TAU`, validated `0 < τ <= 1`, provisional default 0.5), and a `vigilancia` or `sin alerta` case whose certainty is below τ is returned as `revisión clínica`; a `crítico` never changes class.

**Architecture:** A pure `routeByCertainty` in `engine/` decides the class change from the F047 `CertaintyBreakdown.below_tau`. `apps/api` reads τ once at startup (`readTau`, same pattern as `readAllowedSources`), passes it through `buildApp` → `registerIngest` → `interpretMessage` → `computeCertainty`, and applies the routing after `classify`. Classification (`classify`, `POLICY_VERSION`) and the certainty computation (`CERTAINTY_VERSION`) are not touched, so no existing test that pins those versions changes.

**Tech Stack:** TypeScript, Fastify, `node:test`. No new dependency.

**Spec:** `docs/progress/feature-list.json` F048 (criteria: τ configurable by environment; below τ a non-critical goes to review and a critical keeps its class; τ marked provisional), F047 notes (handoff), ADR-003 (a critical never degrades; review only replaces `vigilancia` or `sin alerta`), ADR-010 (class ranks; open question 4: review outranks watch), ADR-014 (τ edge: a complete normal qSOFA case has certainty exactly 0.5; τ must be validated `0 < τ <= 1`).

## Global Constraints

- Branch `feat/f048-tau-routing`. Base: `main` once PR #21 (F047) is merged; if it is not merged yet, branch from `feat/f047-certainty` and open the PR against that branch. No push without approval.
- Routing rule (exact): class `watch` or `no_alert` and `certainty.below_tau === true` → class `review`; every other case unchanged. `review` stays `review`. `critical` is never changed, never rerouted, keeps `requires_confirmation` from F047.
- `below_tau` is `value < tau` (strict). A complete normal qSOFA case has value exactly 0.5; with the default τ = 0.5 it stays `sin alerta`. Pin this.
- `CERTAINTY_TAU` accepts only a decimal number with `0 < τ <= 1`; anything else aborts startup through the existing `invalid configuration` path with a fixed message (no value echoed). Unset means `TAU_PROVISIONAL` (0.5).
- The response keeps `certainty.provisional: true`, `certainty.tau` and `certainty.version`; no new log field or message (AGENTS.md "Logging"); do not change `log-audit.ts`.
- A routed case keeps its original class visible: new response field `routed_from: string | null` (Spanish class name, `null` when not routed); `reason_code` becomes `"low_certainty"` when routed. `highest_reachable_class`, `conflict`, `rules_fired` and `trace` are unchanged.
- No existing test may be edited. If an existing test fails, stop and report; do not relax it.
- `npm run verify` and `npm run scan:phi` exit 0 (check exit codes with `echo $?`, no pipes). Code, commits, plan in English; ADR/PROGRESS in Spanish. No new dependency.

## Review Focus

1. τ out of range or malformed (`0`, `-0.1`, `1.5`, `abc`, `""`, `0x1`, `1e-1`, `NaN`, `Infinity`): startup must reject it; `0` and negatives must not silently disable routing (Task 1).
2. The τ edge: complete normal qSOFA (certainty exactly 0.5) stays `sin alerta` at τ = 0.5; the same case routes to review at τ = 0.6 (Task 3).
3. A critical never leaves `crítico` for any τ in `(0, 1]` over the 27 qSOFA combinations, including τ = 1 (Task 2 and Task 3).
4. A routed `vigilancia` must not lose the fact that it was a watch: `routed_from: "vigilancia"` present, and `highest_reachable_class` still reports what the policy found (Task 3).
5. Several instances in one message: each is routed on its own certainty, and a routed case does not change the class of a sibling (Task 3).
