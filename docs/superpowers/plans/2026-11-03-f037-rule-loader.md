# F037 Rule Loader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Load the active clinical rules from versioned YAML files in `knowledge/rules/`, validate them against a closed schema, hand them to the engine, and compute a stable `rule_set_version` plus the clinical-approval state; an invalid file stops loading with a clear, value-free error.

**Architecture:** A new workspace `packages/rules` (`@decidere/rules`) owns all file and YAML I/O so `engine/` stays pure (ADR-004). Pipeline per file: safe YAML parse -> closed-schema check (rejects unknown keys at every level, which `defineRuleSet` would silently drop) -> collect -> filter `enabled` -> `defineRuleSet(rules, {variables})` -> `rule_set_version` = hash of the canonical form of the active rules plus their metadata.

**Tech Stack:** TypeScript on Node >= 22.18, `node:test`, `node:crypto`/`node:fs` (only in `packages/rules/src/load.ts` and `version.ts`), one new dependency: `yaml` 2.9.1 (see Approval items).

**Spec:** `docs/adr/ADR-002-reglas-como-datos-versionados.md`, `docs/adr/ADR-007-evaluador-de-condiciones.md` (Apéndice B format), `feature-list.json` F037 (acceptance + notes with the F005 final-review consumer notes), `engine/src` public API (`defineRuleSet`, `RuleSet`, `RuleError`).

## Global Constraints

- `engine/` is not modified except to read its public exports. All I/O lives in `packages/rules`. `engine` imports nothing from `packages/rules`.
- YAML parsing options (verified by probe against `yaml` 2.9.1): `parseDocument(text, { version: "1.2", schema: "core", uniqueKeys: true, maxAliasCount: 0, prettyErrors: false })`. Observed behavior to handle: an alias throws `ReferenceError` ("Alias resolution is disabled") at `toJS`; duplicate keys give `YAMLParseError` code `DUPLICATE_KEY`; several documents give `MULTIPLE_DOCS`; unknown tags (`!foo`, `!!js/function`) do NOT error, they become strings plus a warning in `doc.warnings`, so warnings must be rejected; `__proto__: 1` becomes an own key (prototype untouched); `010` is `10` (1.2, not octal); `0x16` is `22` (accepted, documented); `.inf` is a non-finite number (rejected downstream).
- Rule file format v1 (closed, all levels): `format_version: 1`, `id`, `title`, `citation: {source, version, section}`, `clinical_approval: {status, approver, guideline_version}`, optional `enabled` (default `true`), `conditions` (each exactly `id, label, variable, op, value, unit`), `combine` (a condition id string, or exactly one of `all`/`any`/`not`/`atLeast: {n, of}`). No `severity` (class policy is F039). Strings are non-empty and at most 200 characters; `id` matches `^[a-z0-9][a-z0-9._-]{0,63}$` and the file is named `<id>.yaml`.
- `clinical_approval.status` is `pending` or `approved`. `approved` requires non-empty `approver` and `guideline_version`; `pending` allows `null` for both. No dates, no free-text notes.
- Limits: file at most 65536 bytes, at most 200 files in the directory, nesting depth is bounded by the engine (64) and by the file size cap. Non-recursive: only regular files named `*.yaml` directly in the directory; any other entry (subdirectory, symlink, other extension) -> `unsupported_entry`.
- Active rules = `enabled: true`, sorted by `id` (never by file name or file order). Disabled rules are validated but excluded from the engine and from the version. Zero active rules -> `no_active_rules`.
- `loadRuleSet` ALWAYS passes `options.variables` to `defineRuleSet`; the caller must supply it (no default).
- Errors: `RuleLoadError` with closed `code`, `file` (file name only, never a path value from inside the YAML), `path` (positional, e.g. `conditions.2.op`) and optional `line`; `message` is a fixed string per code. No YAML value, key name or parser message is ever copied into an error. Engine `RuleError` is mapped to code `invalid_rule` and its engine code goes in `detail`.
- `rule_set_version` = `"rs-"` + first 16 hex chars of SHA-256 over `canonicalJson({ v: 1, rules: [{ rule, meta }...] })` ordered by rule id, where `rule` is the frozen engine rule and `meta` is `{id, title, citation, clinical_approval}`. `canonicalJson`: recursively sorted object keys, arrays in order, no whitespace.
- Fictional rules only in tests (variables `v1`, `v2`, `v3`, made-up numbers). Clinical thresholds are F038. Files written by tests go to `os.tmpdir()` via `mkdtemp` and are removed afterwards.
- Repo rules: `.ts` import extensions, `import type`, `erasableSyntaxOnly` (no enums/parameter properties), Biome clean, tsc strict. Do not edit existing tests (new test files only). `tsconfig.json` already includes `packages/**/*.ts`.

## Review Focus

- YAML alias/anchor expansion bomb (billion-laughs) must be rejected without expanding; time stays small. Pinned in Task 1.
- Duplicate keys, multiple documents, unknown tags (silently turned into strings), BOM, non-UTF-8 bytes, `__proto__` keys, and a 10 000-deep `[[[...` below the size cap: each gives a closed `RuleLoadError`, never a crash or a raw `ReferenceError`/stack overflow. Pinned in Task 1.
- Unknown or misspelled keys (`threshhold`, `severity`, `enabled: "false"` as a string) at every level must be rejected, not dropped: a typo must not turn into a rule that silently never fires. Pinned in Task 2.
- Number surprises: `"22"` (string), `.nan`, `.inf`, `1e400`, `-0`, `0x16`, `010` — rejected or documented exactly as stated in Global Constraints. Pinned in Task 2.
- A file named differently from its `id`, two files with the same `id`, a disabled rule that would otherwise break loading, reordering/renaming files, comments and key order: version must not depend on them; every real change must change it. Pinned in Task 3.

## Interfaces (all tasks)

```ts
export type RuleLoadErrorCode =
  | "file_too_large" | "too_many_files" | "unsupported_entry" | "not_utf8" | "file_id_mismatch"
  | "yaml_syntax" | "yaml_duplicate_key" | "yaml_alias" | "yaml_tag" | "yaml_multiple_documents"
  | "unknown_key" | "missing_key" | "invalid_type" | "invalid_value"
  | "duplicate_rule_id" | "no_active_rules" | "invalid_rule";
export class RuleLoadError extends Error { readonly code: RuleLoadErrorCode; readonly file?: string; readonly path: string; readonly line?: number; readonly detail?: string }
export type Citation = { source: string; version: string; section: string };
export type ClinicalApproval = { status: "pending" | "approved"; approver: string | null; guideline_version: string | null };
export type RuleDoc = { format_version: 1; id: string; title: string; citation: Citation; clinical_approval: ClinicalApproval; enabled: boolean; conditions: unknown[]; combine: unknown };
export type RuleMeta = { id: string; title: string; citation: Citation; clinical_approval: ClinicalApproval };
export type LoadedRuleSet = { ruleSet: RuleSet; meta: readonly RuleMeta[]; rule_set_version: string; approval: "pending" | "approved" };
export function parseRuleYaml(text: string): unknown;
export function checkRuleDoc(doc: unknown): RuleDoc;
export function canonicalJson(value: unknown): string;
export function computeRuleSetVersion(ruleSet: RuleSet, meta: readonly RuleMeta[]): string;
export function loadRuleSet(dir: string, options: { variables: ReadonlySet<string> }): LoadedRuleSet;
```
`RuleSet` is the branded type from `@decidere/engine`. `meta` has the same order as `ruleSet`. `approval` is `"approved"` only if every active rule is approved, else `"pending"`.
