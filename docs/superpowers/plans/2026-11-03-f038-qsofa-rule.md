# F038 qSOFA Rule v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the published qSOFA criteria as `knowledge/rules/sepsis.qsofa.v1.yaml` (cited, `clinical_approval: pending`) and tests that load the real directory with `loadRuleSet`, pin the transcribed thresholds, and exercise the rule through the engine.

**Architecture:** One data file plus one test file. No production code: the loader (F037) and engine (F005) already do everything. The tests are the only place where the thresholds are pinned, so a threshold edit needs a deliberate test edit (clinical review point via CODEOWNERS).

**Tech Stack:** YAML rule file (format v1), `node:test`, `@decidere/rules`, `@decidere/engine`, `@decidere/schema` (devDependency, workspace link only).

**Spec:** `feature-list.json` F038 (acceptance criteria and notes), ADR-002 section "Formato de archivo v1 y rule_set_version", ADR-007 (Apéndice B example format), ADR-008 (variables `resp_rate`, `sbp`, `gcs`).

## Global Constraints

- Thresholds are transcribed from the published source, never invented ("Umbrales no se inventan"): Sepsis-3, Singer M, et al. JAMA 2016;315(8):801-810, doi:10.1001/jama.2016.0287. Verified 2026-11-03: PubMed abstract (≥2 of: respiratory rate ≥22/min, altered mentation, systolic BP ≤100 mm Hg) and PMC full text (Box 4 "qSOFA (Quick SOFA) Criteria"; section "Screening for Patients Likely to Have Sepsis" says altered mentation "represents any Glasgow Coma Scale score less than 15"). The Box number comes from the PMC rendering: the clinician must re-check it against the JAMA print version.
- Rule file: `knowledge/rules/sepsis.qsofa.v1.yaml`, `format_version: 1`, `id: sepsis.qsofa.v1`, `clinical_approval.status: pending` (`approver: null`, `guideline_version: null`). No `severity` (F039).
- Each condition is referenced exactly once in `combine` (format v1 rule).
- `knowledge/rules/` holds only `*.yaml` rule files: a `.gitkeep` or `README.md` there makes `loadRuleSet` fail with `unsupported_entry`.
- Variables/units must equal the message contract (ADR-008): `resp_rate` `/min`, `sbp` `mm[Hg]`, `gcs` `{score}`. The canonical catalog is F042/F043; until then the provisional set is `resp_rate, sbp, gcs`.
- Do not edit existing tests. Synthetic data only. Code, comments and commits in English; rule `label`/`title` in Spanish (ADR-007).
- Commit format `feat(rules): ...`; one logical change per commit; no push without approval. Branch `feat/f038-qsofa-rule`, stacked on `feat/f037-rule-loader`.

## Review Focus

1. Threshold boundaries: RR 21/22, SBP 100/101, GCS 14/15 (and GCS 3 as an extreme) must flip exactly at the published value → Task 1 boundary table.
2. Missing data: with one criterion missing, ≥2 of 3 is `unknown` if the other two are 1 true + 1 false, `true` if both others are true, `false` if both others are false. Never a silent `false` → Task 1.
3. All 8 true/false combinations of the three criteria: result is true iff ≥2 true → Task 1 truth table.
4. Contract drift: a rule `variable` or `unit` that differs from the message schema would silently never match → Task 1 cross-check against `messageSchema`.
5. Stray file in `knowledge/rules/` (README, `.gitkeep`) breaks the load → Task 1 directory test.

```yaml
  status: pending
  approver: null
  guideline_version: null
conditions:
  - { id: fr_alta,  label: "Frecuencia respiratoria alta",       variable: resp_rate, op: ">=", value: 22,  unit: "/min" }
  - { id: ta_baja,  label: "Presión sistólica baja",             variable: sbp,       op: "<=", value: 100, unit: "mm[Hg]" }
  - { id: gcs_bajo, label: "Alteración del estado mental (GCS)", variable: gcs,       op: "<",  value: 15,  unit: "{score}" }

  atLeast: { n: 2, of: [fr_alta, ta_baja, gcs_bajo] }
```
