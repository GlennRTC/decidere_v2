# F047 Deterministic certainty (completeness, margin, conflict) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every `results[]` entry of `POST /v1/messages` carries a `certainty` object with `completeness`, `margin`, `conflict` and their minimum, plus a `requires_confirmation` flag that only a `crítico` below τ can receive; the class itself is never changed by certainty.

**Architecture:** A pure function `computeCertainty` in `engine/src/certainty.ts` (no I/O, no new dependency) reads the rule set, the `RuleSetResult` trace and the `ClassDecision` from `classify`, and returns the three components. Bands per variable live in a provisional table in the same file (same pattern as `POLICY_VERSION` in ADR-010). `apps/api/src/interpret.ts` calls it after `classify` and replaces the `certainty: null` placeholder. Routing non-critical cases to `revisión clínica` below τ and making τ an env variable are F048, not here.

**Tech Stack:** TypeScript, `node:test`. No new dependency.

**Spec:** `docs/progress/feature-list.json` F047 (and F008 acceptance criteria), ADR-003 (certainty = min of three components in [0,1]; critical never degrades), ADR-007 (best/worst case, `atLeast` counts `t,u,f,min,max` in the trace), ADR-010 (class policy; `requires_confirmation` is owned by certainty), ADR-013 handoffs (completeness counted by criteria).

## Global Constraints

- Certainty = `min(completeness, margin, conflict)`, each in `[0,1]`, returned separately (ADR-003). No weighted average, no product, no LLM.
- Deterministic: same input, same output. No `Date`, no randomness, no I/O in `engine/`.
- `computeCertainty` never changes `ClassDecision.class`; a `crítico` is never downgraded (ADR-003).
- All bands, the `CERTAINTY_VERSION`, and `TAU_PROVISIONAL` are provisional and labelled as such in code and in the response (`provisional: true`); they need clinical review and calibration (F049).
- No clinical values, variable names or rule ids in error messages or logs (ADR-001/008). The log may carry the certainty number only (AGENTS.md "Logging" allows `certeza`); never the component trace.
- Existing test `apps/api/src/interpret.test.ts` asserts `certainty === null`; changing it needs explicit user approval (AGENTS.md). Do not edit any other existing test.
- Branch `feat/f047-certainty` from updated `main`; no push without approval. `npm run verify` and `npm run scan:phi` exit 0 before marking `passing`. Code, commits and plan in English; ADR/PROGRESS in Spanish.

## Definitions (decided here, to be confirmed clinically)

- **Completeness** per rule: if the root combinator is `atLeast`, `1 - u / (t + u + f)` from the root trace entry (denominator = criteria, the root's children; SIRS has 4, qSOFA 3). Otherwise `known leaves / total leaves`. Case value = minimum over rules.
- **Margin**: for each known leaf, `min(1, |observed - threshold| / band[variable])`. Case value = minimum over known leaves of all rules; no known leaf gives `1` (completeness already carries that loss). A variable without a band gives `0` for its leaves (fail conservative, never fail open).
- **Conflict**: `(rules whose class equals the decided class) / (number of rules)` from `ClassDecision.basis`; one rule gives `1`.
- **Provisional bands** (one number per catalog variable): `resp_rate` 4 `/min`, `sbp` 10 `mm[Hg]`, `gcs` 1 `{score}`, `heart_rate` 10 `/min`, `temperature` 0.5 `Cel`, `wbc` 2 `10*3/uL`, `paco2` 4 `mm[Hg]`, `bands_pct` 2 `%`.
- **τ**: `TAU_PROVISIONAL = 0.5`, exported, passed as a parameter. `below_tau = value < tau`. `requires_confirmation = decision.class === "critical" && below_tau`.

## Review Focus

1. Critical with missing data keeps its class: qSOFA `resp_rate` 30 and `sbp` 80 with `gcs` missing is `crítico` and certainty below 1 (Task 2).
2. Property: over the 27 qSOFA combinations of `{true, false, missing}`, no case with `highest_reachable_class: critical` is `sin alerta`, and every `crítico` keeps its class whatever the certainty (Task 2).
3. Boundary values: `resp_rate` exactly 22 gives margin 0; 22 ± one full band gives margin 1; margin never leaves `[0,1]` (Task 1).
4. A catalog variable without a band, and a rule referencing a variable outside the table, must not raise certainty (Task 1; Task 3 pins that every `DELIVERABLE_VARIABLES` entry has a band).
5. The POST response and the structured log: `certainty` is an object in the body and a plain number in the log line, and the log audit still passes (Task 3).
