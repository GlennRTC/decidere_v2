# F005 Rule Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure, dependency-free `engine/` package that validates an in-memory rule set once, then evaluates rules against canonical variables with three-valued logic and returns per-rule results plus a complete trace.

**Architecture:** `defineRuleSet(rules, options?)` validates and deep-freezes a copy (a rule set that fails never loads). `evaluateRuleSet(ruleSet, input)` evaluates every condition of every rule, in declaration order, with no short-circuit, and returns `{ rules: RuleResult[], fired: string[] }`. The class (crítico/vigilancia/sin alerta/revisión) is NOT computed here: it is F039. YAML loading, `rule_set_version` and `clinical_approval` are F037.

**Tech Stack:** TypeScript on Node >= 22.18 (type stripping), `node:test`, no runtime dependency.

**Spec:** `docs/adr/ADR-007-evaluador-de-condiciones.md` (decision, Apéndice C is the reference semantics; the spike code itself is not in the repo), `docs/adr/ADR-002-reglas-como-datos-versionados.md`, `feature-list.json` F005 (acceptance criteria), AGENTS.md "Reglas no negociables de dominio".

## Global Constraints

- No runtime dependencies and no imports other than relative `./*.ts` files and `import type`. No `node:*` import, no `process`, `Date`, `Math.random`, `fetch`, `eval`, `new Function` in non-test sources (ADR-004, F005 criterion 1).
- Truth values: `Tri = boolean | "unknown"`. A missing, `null`, non-number, `NaN` or infinite input is `"unknown"`; reason `"missing"` for `undefined`/`null`/absent, `"invalid"` for anything else. `0` is a value. A numeric string (`"3"`) is NOT converted.
- Operator table is closed: `>`, `>=`, `<`, `<=`, `==`. Combinators: `all`, `any`, `not`, `atLeast {n, of}`. Max nesting depth 64 (ADR-007, "por confirmar").
- Every condition is evaluated; the trace lists conditions in declaration order, then combinator nodes in post-order with positional ids (`combine`, `combine.0`, `combine.0.1`).
- `atLeast`: true if T >= n; false if T + U < n; otherwise unknown. Trace carries `t`, `u`, `f`, `min = t`, `max = t + u`.
- Load-time errors are `RuleError` with a closed `code` and a `path` (positions only). A message never contains a rule value, key name or input value.
- Unit conversion and rounding are the mapper's job (F043); the engine compares numbers as given. `==` on derived floats is not recommended (ADR-007 Apéndice A, fila 6).
- No clinical thresholds are invented. Tests use fictional variables (`v1`, `v2`, `v3`) and fictional numbers, never qSOFA values (F038 transcribes those with a citation).
- TypeScript rules of the repo: `.ts` import extensions, `import type`, `erasableSyntaxOnly` (no enums, no parameter properties), tsc strict, Biome clean.
- Do not edit existing tests. `tsconfig.json` `include` gains `engine/**/*.ts`.

## Review Focus

- Hostile rule shapes (`null`, arrays, `atLeast: null`, `atLeast: 3`, a `__proto__` key, 10 000 nested `not`) must raise `RuleError`, never `TypeError`/`RangeError`. Pinned in Task 1.
- Hostile input: inherited properties (`constructor`, `toString`, a prototype with `v1`) and `__proto__` as a variable name are ignored (`unknown/missing`); the input object is not mutated. Pinned in Task 2.
- Mutating the original rule objects after `defineRuleSet` must not change results (frozen copy). Pinned in Task 1.
- Unknown mixed with false/true: `all` with a false stays false, `any` with a true stays true, `not unknown` stays unknown; if the best case reaches an `atLeast` threshold the result is never `false`. Pinned in Task 3 against a brute-force oracle.
- The same condition id may appear in two different rules (ids are unique per rule only); duplicate rule ids are rejected. Pinned in Tasks 1 and 4.

## Interfaces (all tasks)

```ts
export type Tri = boolean | "unknown";
export type Op = ">" | ">=" | "<" | "<=" | "==";
export type Condition = { id: string; label: string; variable: string; op: Op; value: number; unit: string };
export type Node = string | { all: Node[] } | { any: Node[] } | { not: Node } | { atLeast: { n: number; of: Node[] } };
export type Rule = { id: string; conditions: Condition[]; combine: Node };
export type RuleSet = readonly Readonly<Rule>[]; // deep-frozen, produced only by defineRuleSet
export type RuleErrorCode = "invalid_rule_set" | "invalid_rule" | "invalid_condition" | "invalid_combinator" | "duplicate_id" | "unknown_reference" | "unknown_variable" | "too_deep";
export class RuleError extends Error { code: RuleErrorCode; path: string }
export type Input = Readonly<Record<string, unknown>>;
export type TraceEntry =
  | { id: string; kind: "leaf"; result: Tri; observed: number | null; op: Op; threshold: number; unit: string; label: string; reason?: "missing" | "invalid" }
  | { id: string; kind: "all" | "any" | "not"; result: Tri }
  | { id: string; kind: "atLeast"; result: Tri; t: number; u: number; f: number; min: number; max: number };
export type RuleResult = { rule_id: string; result: Tri; trace: TraceEntry[] };
export type RuleSetResult = { rules: RuleResult[]; fired: string[] };
export function defineRuleSet(rules: unknown, options?: { variables?: ReadonlySet<string> }): RuleSet;
export function evaluateRuleSet(ruleSet: RuleSet, input: Input): RuleSetResult;
```
